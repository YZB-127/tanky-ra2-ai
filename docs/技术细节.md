# 技术细节：等长改法、保留原值、女神像加厚

这份文档解释"为什么这么改"，以及"想自己调该怎么改"。

---

## 1. 本模式到底是什么

原版 `rules.ini` 里，船厂（盟军 `[GAYARD]`、苏军 `[NAYARD]`）的血量是 **1500**，是全游戏最硬的建筑。
本模式把**所有**死亡判定用到的血量键都改成 1500：

| 键 | 作用 | 位置 |
|---|---|---|
| `Strength` | 步兵 / 载具 / 飞机 / 建筑 / 地形的生命上限 | 各类型段落 |
| `TreeStrength` | 树木 | `[General]` |
| `BridgeStrength` | 桥梁 | `[CombatDamage]` |

`TiberiumStrength` 是**泰矿连锁爆炸阈值**，不是血量，不要动。

---

## 2. 为什么不需要打 exe 补丁（和 5 血版的区别）

5 血版崩溃的根因是维修费计算里的整数除法：

```
维修费 = max(1, ( 造价 / ( 血量上限 / RepairStep ) ) × RepairPercent )
                          └── 血量 < RepairStep 时截断成 0 → 下一步除零 ──┘
```

- 5 血 + `RepairStep=8` → `5/8 = 0` → `EXCEPTION_INT_DIVIDE_BY_ZERO`
- 本模式 1500 血 + `RepairStep=8` → `1500/8 = 187`，**永远安全**

所以本模式**保持原版 `RepairStep=8` / `IRepairStep=20`，也不给 `game.exe` 打补丁**。
5 血版那个 `mov eax,5` 补丁（把商固定成 5）在 1500 血下会让每次维修的费用按"血量/5"算，
也就是正常维修费的 **5 倍以上**——那是给 5 血量身定的，绝不能混用。

唯一要注意的是"0 血"类型：`[DeathDummy]` 原版有段落但没有 `Strength` 键 → 0 血 → `0/8=0` → 仍会除零。
`rules.ini` 里已给它补上 `Strength=1500`。

## 3. 任务包里的"地图自带覆盖"

RA2 的地图/任务包可以**自带规则覆盖**，优先级**高于** `rules.ini`：

```
[E2]
Name=Conscript
Strength=100      ← 这句会盖掉 rules.ini 里的值
```

所以"只改 `rules.ini`"在任务里会失效，必须改数据包内部。但：

**`.mix` / `.mmx` / `.yro` 的索引用 Blowfish 加密**，索引里记着每个内部文件的偏移和长度。
改长度就得重写加密索引，风险和成本都很高。所以本仓库的硬规矩是：

> **一律等长替换。文件大小一个字节都不许变。**

### 三种改法

| 情况 | 做法 | 例子 |
|---|---|---|
| 类型在 `rules.ini` 里有段落 | 把 `Strength=` 的 `S` 换成 `;` 注释掉（等长），让它回落到 `rules.ini` 的 1500 | `Strength=1000` → `;trength=1000` |
| 任务图内自带类型、原值 ≥ 4 位 | 原地写 1500，多余位数用空格补齐 | `Strength=1000` → `Strength=1500`；`Strength=50000` → `Strength=1500  ` |
| 任务图内自带类型、原值只有 1~3 位 | 值扩成 1500 会多出 1~3 字节，就在**同一段落内**删掉等量字节 | `Strength=250` → `Strength=1500` + 删 1 字节 |

### 第 3 种怎么"借字节"

只删**同一段落内部**、语义为空的东西，按优先级：

1. 空行：`\r\n\r\n` → `\r\n`（借 2 字节）
2. 注释行：例如 `;Ammo=10`（借整行长度）
3. 重复的逗号列表项：例如 `VoiceDie=DEDMAN1,DEDMAN2,DEDMAN2,...` 里的第二个 `DEDMAN2`（借 8 字节）

删的位置必须在该段落的 `Strength=` 之后、下一个 `[段落]` 之前，这样"扩 1 字节 + 删 1 字节"
净长度为 0，而且不会跨过任何地图分界。

> ⚠️ 反过来做（在别处删）就能把某张地图的开头切掉几个字节，那是 silent corruption。
> 所以改完一定要做结构自查。

## 4. 改完必须做的结构自查

拿改好的文件跟**原版备份**逐项对比，必须全部一致：

- 文件大小
- 段头总数（`^\[...\]`）
- 这些标记的出现次数：`[Basic]` `[Header]` `[Map]` `[MultiMaps]` `[Digest]`
  `[IsoMapPack5]` `[Structures]` `[Units]` `[Infantry]` `[Triggers]` `[Waypoints]`
- 不能出现 `asic]` / `eader]` / `ultiMaps]` / `igest]` 这种"少了左括号"的残片

只要有一条不符，就说明某张图的头被切了，必须回滚重来。

## 5. 为什么"原值 > 1500 就保留"

任务图里那些 2000 / 2500 / 8500 / 30000 / 50000 / 100000 的值**不是漏改**，是关卡作者
把某些目标/地标**故意做硬**了：

- 盟军第一关：自由女神像 10000（必须守住）
- 苏联/盟军后期关：纽约大楼、巴黎塔 30000~50000（剧本里的地标，拆起来得有过程）
- 苏军基地 `NACNST` 30000、核电站 `NANRCT` 32000、导弹井 `NAMISL` 100000（AI 的核心资产）
- 精神信标 `NAPSYB` 2500（苏军第三关的关键建筑）

把它们压到 1500 的后果是实测过的：**盟军第一关一开局女神像就被拆，关卡直接失败**。
所以现在是"**只把比船厂脆的东西抬到 1500，比船厂硬的原样保留**"。

---

## 6. 为什么女神像还要额外加厚到 99999

"保留原值"只能保证它跟原版一样硬。但本模式里**进攻方也变 1500 血了**：

- 原版：苏军那波"`BG1 - Attack Statue of Liberty`"部队很快被打光，雕像只挨几下
- 本模式：那波部队磨半天不死，火力全砸在雕像上 → 10000 血也守不住

所以盟军第一关的 `CANEWY04` 单独提到 **99999**（等长：`Strength=10000` 和 `Strength=99999`
都是 14 字节，纯数字替换）。苏军第三关的雕像保持 10000，因为那关它是地标而不是"必须守住的失败条件"。

## 7. 降负载那几项是干什么的

苏军第三关结尾"盟军单位被大批控制"的瞬间崩过一次：

```
Error code: EXCEPTION_ACCESS_VIOLATION
Access address: 00001104 was written to.
Exception occurred at 00787B2A     ← 链表 + 位图 + 引用计数 那段代码
```

`Ecx=0x1100` 这种"小整数被当指针"，说明是**更早的内存写坏**，到这一步才炸。
全员 1500 血让场上活着的对象更多、战斗更久，正好是这类"堆压力型"崩溃的高发场景。
所以额外压了碎片和烟尘：

| 键 | 处理 | 代价 |
|---|---|---|
| `MaxDebris` | ≤ 4 | 碎片动画变少 |
| `MinDebris` | ≤ 1 | 同上 |
| `DamageParticleSystems` | 每类 1 套（建筑 `BigGreySmokeSys` / 单位 `SmallGreySSys`） | 烟尘变少 |
| `[OilExplosionWH] DelayKillFrames` | 15 | 连环爆分帧更明显 |

**连锁伤害一点没改**：`DeathWeapon=`、`CausesDelayKill=yes`、`CellSpread=` 全部原样。

---

## 8. 存档的坑（最容易误判的一条）

红警的 `.sav` 里存的是**当时那份场景**（解析后的对象、触发、以及各类型的血量）。
所以：

- 应用新规则后，**读旧存档仍然用旧血量** → 看起来像"改了没用"
- 正确做法：**新开**关卡/遭遇战；战役从"新战役"进
- 实在想验证：把 `ALL01T.sav` 之类先改名藏起来，逼游戏重新生成场景

---

## 9. 想自己调，改哪里

| 想干什么 | 改哪里 |
|---|---|
| 血量数值（比如改 3000） | `rules.ini` 里所有 `Strength`；再把 `apply_tanky_mod.py` 顶部的 `HP` 改掉重跑 |
| 某个必须守的目标又要被拆 | 用 `set_override.py` 的思路单独给它加厚，但要**保持位数一致**（等长） |
| 画面更流畅 | 继续压 `MaxDebris` / 把 `DamageParticleSystems` 整段注释掉 |
| 维修更快 | `[General] RepairStep`（**不能大于最小血量**，本模式最小 1500，别乱调） |

改 `rules.ini` 里的 `Strength` 是安全的（松散文件，长度随便变）。
改任务包**永远只能等长**——这一点没有例外。
